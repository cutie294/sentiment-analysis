# 02. UI 디자인 및 구현 가이드

## 1. 참고 이미지 해석
첨부된 이미지는 차분하고 여백이 큰 꽃 중심의 감성 랜딩 페이지다. 다음 시각적 특징을 디자인 기준으로 삼는다.

- 배경: 따뜻한 회색 또는 아주 옅은 회백색.
- 메인 비주얼: 중앙에 크게 배치된 연분홍 꽃 사진.
- 타이포그래피: 가늘고 우아한 산세리프 또는 대비가 강하지 않은 디스플레이 글꼴.
- 구성: 넓은 여백, 얇은 세로 구분선, 절제된 정보량.
- 포인트: 오른쪽 아래 작은 이미지 카드처럼 보이는 보조 요소.
- 분위기: 조용함, 섬세함, 사색적, 따뜻함.

첨부 이미지는 분위기 참고 자료다. 이미지 속 잘린 문구나 원본 브랜드를 복제하지 않는다. 동일한 꽃 사진을 사용할 수 있는 권리가 확인되지 않으면 직접 촬영·생성·라이선스 확보한 이미지 또는 CSS 배경을 사용한다.

## 2. 화면 구성
단일 페이지로 구현한다.

1. **헤더**: 좌측 서비스 워드마크(예: `mood / note`), 우측 작은 설명 또는 `TEXT SENTIMENT`.
2. **히어로 영역**: 큰 제목 “마음의 결을 읽다”와 짧은 설명. 배경에는 연분홍 꽃 이미지를 크게 배치한다.
3. **입력 카드/영역**: “오늘의 문장을 남겨보세요” 안내, 여러 줄 텍스트 입력창, 글자 수 표시, 분석 버튼.
4. **개인정보 안내**: 텍스트와 결과가 저장된다는 사실을 입력 영역 아래에 명확히 표시.
5. **결과 영역**: 분석 후에만 노출. 감정 라벨, 신뢰도 백분율, 분석 이유를 표시.
6. **오류 영역**: 문제가 생겼을 때 결과 영역과 구분되는 안내문과 재시도 유도.
7. **푸터**: “AI 분석은 참고용이며 감정을 단정하지 않습니다.” 안내.

## 3. 레이아웃 기준
- 데스크톱 기준 콘텐츠 최대 너비는 1120px, 본문 읽기 영역은 680px 내외.
- 화면 가장자리 여백은 데스크톱 32~56px, 모바일 20px 이상.
- 히어로는 첫 화면에서 시각적 중심이 되되 입력 기능을 찾기 어렵게 만들지 않는다.
- 꽃 이미지는 텍스트와 입력 컨트롤의 대비를 방해하지 않도록 밝기·투명도·오버레이를 조절한다.
- 세로선은 장식 요소로만 사용하고 읽기 흐름을 가르지 않는다.
- 결과 카드는 입력 영역 바로 아래에 표시해 분석 후 시선을 자연스럽게 이어준다.

## 4. 색상·타이포그래피 토큰
아래 값은 초기 기준이며 실제 렌더링 후 대비를 검증한다.

```css
:root {
  --color-bg: #e9e7e7;
  --color-surface: #f7f5f4;
  --color-text: #292526;
  --color-muted: #777174;
  --color-line: rgba(55, 48, 52, 0.16);
  --color-pink: #d9a9c8;
  --color-positive: #587d69;
  --color-negative: #a65f68;
  --color-neutral: #77777b;
  --content-width: 1120px;
  --reading-width: 680px;
}
```

- 제목은 큰 크기와 가는 굵기를 사용하되 본문은 읽기 쉬운 굵기로 한다.
- 외부 웹 폰트는 로딩 실패 시 시스템 폰트로 자연스럽게 대체한다.
- 본문 기본 크기는 데스크톱 16px 이상, 모바일 15px 이상을 권장한다.
- 감정 결과는 색만으로 표현하지 말고 “긍정”, “부정”, “중립” 텍스트를 반드시 함께 표시한다.

## 5. 반응형 규칙
- 360px~767px: 단일 열, 꽃 이미지는 배경 장식으로 축소하거나 일부 크롭, 버튼은 충분한 터치 높이 확보.
- 768px~1199px: 여백을 줄이고 콘텐츠 너비를 화면에 맞춘다.
- 1200px 이상: 최대 너비를 유지하고 중앙 정렬한다.
- 모든 구간에서 가로 스크롤이 없어야 한다.
- `prefers-reduced-motion: reduce`를 존중하고 필수 기능에 애니메이션을 사용하지 않는다.

## 6. 상태별 UI
- 기본: 입력 영역과 안내 문구.
- 입력 중: 글자 수 표시, 최대 길이 초과 방지.
- 로딩: 버튼 비활성화, “문장을 살펴보고 있어요…” 표시.
- 성공: 감정 라벨, 추정 신뢰도, 분석 이유.
- 실패: 원인별 쉬운 한국어 메시지, 재시도 가능 상태.
- 빈 입력: 서버 요청 없이 입력 영역 근처에 안내.

## 7. 접근성 및 완료 기준
- 모든 입력에는 보이는 레이블 또는 명시적 `aria-label`이 있다.
- 버튼과 입력은 키보드로 조작 가능하며 포커스 링이 보인다.
- 결과와 오류는 `aria-live="polite"` 영역에서 읽힐 수 있다.
- 색상 대비를 확인하고 텍스트 확대 시 내용이 잘리지 않는다.
- 360px, 768px, 1440px 폭에서 핵심 기능을 확인한다.
- 스크린리더에서 결과 라벨·신뢰도·이유가 의미 있는 순서로 읽힌다.
