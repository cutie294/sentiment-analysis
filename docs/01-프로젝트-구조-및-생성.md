# 01. 프로젝트 구조 및 생성 지침

## 1. 목적
에이전트가 같은 구조를 만들도록 폴더와 파일의 책임을 고정한다. 먼저 아래 구조를 만든다.

```text
sentiment-service/
├─ AGENTS.md
├─ PRD.md
├─ package.json
├─ .gitignore
├─ .env.example
├─ index.html
├─ api/
│  └─ analyze.js
├─ assets/
│  └─ (선택 이미지 파일)
├─ css/
│  └─ styles.css
├─ js/
│  └─ app.js
├─ lib/
│  ├─ openai.js
│  ├─ supabase.js
│  ├─ validation.js
│  └─ errors.js
├─ supabase/
│  └─ schema.sql
└─ docs/
   ├─ 01-프로젝트-구조-및-생성.md
   ├─ 02-UI-가이드.md
   ├─ 03-프런트엔드-구현.md
   ├─ 04-백엔드-및-AI-구현.md
   ├─ 05-데이터베이스-및-보안.md
   └─ 06-테스트-및-배포.md
```

## 2. 생성 순서
1. Node.js LTS가 설치되어 있는지 `node -v`, `npm -v`로 확인한다.
2. 프로젝트 폴더를 만들고 `npm init -y`를 실행한다.
3. 필요한 서버 라이브러리만 설치한다: `openai`, `@supabase/supabase-js`.
4. 개발 편의를 위해 필요하면 `vercel`을 개발 의존성으로 설치한다.
5. 위 폴더와 파일을 생성한다.
6. `package.json`에 `dev`, `start` 스크립트를 구성한다. Vercel CLI 사용 시 `dev`는 `vercel dev`로 한다.
7. `.gitignore`에 `node_modules/`, `.env`, `.env.local`, `.vercel/`을 추가한다.
8. `.env.example`을 작성하되 실제 키는 넣지 않는다.

## 3. 파일별 책임
- `index.html`: 의미 있는 HTML 구조와 접근성 레이블.
- `css/styles.css`: 모든 화면 스타일과 반응형 규칙.
- `js/app.js`: 입력 이벤트, 로딩, API 호출, 결과 렌더링.
- `api/analyze.js`: Vercel 서버 API 진입점.
- `lib/validation.js`: 서버 입력 검증과 길이 제한.
- `lib/openai.js`: OpenAI 요청 및 결과 스키마 검증.
- `lib/supabase.js`: 서버 전용 Supabase 클라이언트.
- `lib/errors.js`: 내부 오류를 표준 API 오류로 변환.
- `supabase/schema.sql`: 테이블 및 인덱스 생성 SQL.

## 4. 의존성 제약
- 기본 UI는 바닐라 HTML/CSS/JavaScript로 구현한다.
- UI 프레임워크, CSS 프레임워크, 빌드 도구는 추가하지 않는다.
- 서버 라이브러리 외 의존성은 필요성을 설명할 수 있을 때만 추가한다.
- Node.js와 Vercel의 모듈 방식이 일치하도록 `package.json`의 `type`과 파일 문법을 맞춘다.

## 5. 완료 및 검증
- 위 폴더 구조가 존재한다.
- `.env.example`에 필요한 변수명이 빠짐없이 있다.
- 실제 비밀 키가 Git 추적 대상이 아니다.
- `npm install`이 성공한다.
- `npm run dev`로 로컬 실행을 시작할 수 있다.
