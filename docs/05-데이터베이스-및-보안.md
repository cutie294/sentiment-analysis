# 05. Supabase 데이터베이스 및 보안 지침

## 1. 저장 목적
성공한 감성 분석 요청을 운영 데이터로 저장한다. 이번 버전에는 사용자 계정이나 분석 기록 화면을 만들지 않는다. 데이터베이스 저장은 서버 API에서만 수행한다.

## 2. 테이블 정의
테이블명: `sentiment_analyses`

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | `uuid` | PK, 기본값 `gen_random_uuid()` | 분석 ID |
| `input_text` | `text` | NOT NULL | 사용자가 입력한 문장 |
| `sentiment` | `text` | CHECK | `positive`, `negative`, `neutral` |
| `confidence` | `integer` | 0~100 CHECK | 모델 추정 신뢰도 |
| `reason` | `text` | NOT NULL | 분석 이유 |
| `model` | `text` | NULL 허용 | 사용한 모델 식별자 |
| `created_at` | `timestamptz` | 기본값 `now()` | 생성 시각 |

다음 SQL을 `supabase/schema.sql`에 작성한다.

```sql
create table if not exists public.sentiment_analyses (
  id uuid primary key default gen_random_uuid(),
  input_text text not null,
  sentiment text not null check (sentiment in ('positive', 'negative', 'neutral')),
  confidence integer not null check (confidence between 0 and 100),
  reason text not null,
  model text,
  created_at timestamptz not null default now()
);

create index if not exists sentiment_analyses_created_at_idx
  on public.sentiment_analyses (created_at desc);

alter table public.sentiment_analyses enable row level security;
```

## 3. 접근 권한
- 브라우저에서 Supabase 테이블을 직접 조회·삽입하지 않는다.
- 서버에서만 `SUPABASE_SERVICE_ROLE_KEY`를 사용한다.
- 서비스 롤 키는 RLS를 우회할 수 있으므로 절대 공개하지 않는다.
- 테이블 RLS를 활성화하고, 익명 사용자에게 직접 접근 가능한 정책을 만들지 않는다.
- API는 입력 검증을 통과한 요청만 저장한다.

## 4. 저장 규칙
- AI 결과 검증이 끝난 후 저장한다.
- `input_text`, `sentiment`, `confidence`, `reason`, `model`을 저장한다.
- DB가 반환한 `id`를 API 성공 응답의 `data.id`로 사용한다.
- DB 저장 실패 시 성공으로 응답하지 않는다.
- 원문 저장은 개인정보 위험이 있으므로 입력창 근처에 저장 사실을 고지한다.
- 공개 전 운영자는 데이터 보관 기간, 삭제 요청 처리, 개인정보 처리방침을 확정해야 한다. 에이전트가 법률 자문이나 임의의 보관 기간을 만들지 않는다.

## 5. 환경 변수
`.env.example`:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

- `OPENAI_MODEL`은 사용자가 선택한 OpenAI 모델 ID를 입력한다.
- Vercel 프로젝트 설정의 Environment Variables에도 동일한 변수를 등록한다.
- 로컬 `.env.local`은 Git에 커밋하지 않는다.
- 환경 변수가 누락된 경우 서버 시작 또는 요청 단계에서 명확한 설정 오류를 반환한다.

## 6. 완료 및 검증
- SQL을 Supabase SQL Editor에서 실행할 수 있다.
- 테이블과 인덱스가 생성된다.
- RLS가 활성화되어 있다.
- 공개 키나 서비스 롤 키가 프런트엔드 파일에 없다.
- 정상 분석 1건이 지정 컬럼에 저장된다.
- DB 연결 실패 시 오류 응답이 반환된다.
- 실제 운영 전에 개인정보 안내·보관 기간·삭제 정책이 확정되었는지 확인한다.
