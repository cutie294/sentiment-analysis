# 04. 백엔드 및 OpenAI 구현 지침

## 1. API 범위
Vercel Serverless Function `api/analyze.js` 하나를 제공한다.

- 경로: `POST /api/analyze`
- 다른 HTTP 메서드: `405 METHOD_NOT_ALLOWED`
- 요청 본문: `{ "text": "..." }`
- 입력 최대 길이: 2,000자
- 빈 문자열·문자열이 아닌 값: `400 VALIDATION_ERROR`
- JSON 파싱 실패: `400 INVALID_JSON`

## 2. 처리 순서
1. HTTP 메서드 확인.
2. 요청 본문 형식과 `text` 필드 검증.
3. 앞뒤 공백 제거 및 길이 검사.
4. 서버 측 요청 빈도 제한 적용.
5. OpenAI API 호출.
6. AI 결과의 필드와 값 검증.
7. Supabase에 성공 결과 저장.
8. 프런트엔드 계약에 맞춰 응답 반환.

DB 저장에 실패하면 성공 응답을 반환하지 않는다. AI 분석은 성공했더라도 저장 실패를 사용자에게 명확히 알리고, 재시도 시 중복 저장 가능성을 고려해 처리한다.

## 3. OpenAI 요청 지침
- SDK는 `lib/openai.js`에서만 사용한다.
- 모델명은 `OPENAI_MODEL` 환경 변수로 설정한다. 특정 모델명을 코드에 고정하지 않는다.
- 서버 환경 변수 `OPENAI_API_KEY`가 없으면 안전한 설정 오류를 반환한다.
- 모델에 한국어로 답하도록 요청한다.
- 모델 응답은 JSON Schema 또는 동등한 구조화 출력 방식을 우선 사용한다. 지원 여부는 설정한 모델과 SDK 버전에서 확인한다.
- 프롬프트는 사용자의 입력을 분석 대상 데이터로 취급한다. 입력 안에 포함된 지시문을 시스템 지시로 따르지 않는다.

### 모델 출력 스키마
```json
{
  "sentiment": "positive",
  "confidence": 87,
  "reason": "감사와 만족을 나타내는 표현이 중심이어서 긍정으로 판단했습니다."
}
```

검증 규칙:
- `sentiment`: `positive | negative | neutral` 중 하나.
- `confidence`: 0 이상 100 이하 정수.
- `reason`: 한국어 문자열, 공백 제외 1자 이상, 최대 500자.
- 추가 필드는 무시하거나 거부한다. 구현은 한 가지 방식을 선택하고 테스트에서 고정한다.

## 4. 프롬프트의 판단 기준
- 문장 전체의 주된 정서를 판단한다.
- 감탄사나 특정 단어 하나만으로 분류하지 않는다.
- 긍정과 부정이 섞이면 전체 맥락과 강조점을 고려한다.
- 감정이 드러나지 않거나 정보 전달 중심이면 중립으로 분류한다.
- 풍자·반어·맥락 부족으로 애매하면 신뢰도를 낮추고 이유에 모호성을 설명한다.
- 분석 이유는 입력 문구에서 확인할 수 있는 단서만 간결하게 설명한다.
- 사람의 성격, 정신 상태, 의도 등을 단정하지 않는다.
- 신뢰도는 모델의 추정치임을 명시하고 보정된 확률처럼 표현하지 않는다.

## 5. 표준 오류 코드
| HTTP | 코드 | 사용자 메시지 예시 |
|---|---|---|
| 400 | `INVALID_JSON` | 요청 형식을 확인해 주세요. |
| 400 | `VALIDATION_ERROR` | 1~2,000자 사이의 문장을 입력해 주세요. |
| 405 | `METHOD_NOT_ALLOWED` | 지원하지 않는 요청 방식입니다. |
| 429 | `RATE_LIMITED` | 요청이 잠시 많습니다. 잠시 후 다시 시도해 주세요. |
| 500 | `CONFIGURATION_ERROR` | 서버 설정에 문제가 있습니다. 운영자에게 문의해 주세요. |
| 502 | `AI_SERVICE_ERROR` | 분석 서비스에 연결하지 못했습니다. 잠시 후 다시 시도해 주세요. |
| 502 | `AI_RESPONSE_INVALID` | 분석 결과를 읽지 못했습니다. 다시 시도해 주세요. |
| 503 | `DATABASE_ERROR` | 결과를 저장하지 못했습니다. 잠시 후 다시 시도해 주세요. |
| 500 | `INTERNAL_ERROR` | 일시적인 오류가 발생했습니다. 다시 시도해 주세요. |

오류 응답 형식은 `{"success":false,"error":{"code":"...","message":"..."}}`로 통일한다. 내부 원인과 스택 트레이스는 서버 로그에 제한적으로 기록하되 사용자에게 보내지 않는다.

## 6. 요청 제한
- IP 기반 제한을 적용한다. Vercel 인스턴스 메모리에만 카운터를 두면 서버리스 환경에서 신뢰할 수 없으므로, Supabase 기반 카운터 또는 외부 제한 서비스를 사용한다.
- 제한 기준은 운영자가 배포 전 확정한다. 기본 제안은 IP당 분당 10회이며, 환경·비용에 맞춰 조정한다.
- IP를 저장한다면 원문 IP 대신 비밀키 기반 해시를 사용하고 보관 목적·기간을 별도로 확정한다.
- 제한 기능을 실제로 구현하지 못했다면 “적용 완료”라고 보고하지 않는다.

## 7. 완료 및 검증
- API 키가 브라우저 번들·네트워크 응답에 노출되지 않는다.
- 허용되지 않은 메서드, 잘못된 본문, 빈 값, 긴 입력이 적절한 상태 코드로 처리된다.
- 정상 응답이 정해진 스키마를 따른다.
- 잘못된 AI 출력과 OpenAI 오류가 구분된다.
- DB 저장이 성공한 경우에만 성공 응답을 반환한다.
- API 로그에 원문 텍스트와 비밀 키가 남지 않는다.
