# 03. 프런트엔드 구현 지침

## 1. 담당 범위
`index.html`, `css/styles.css`, `js/app.js`를 구현한다. 프런트엔드는 화면 표시와 API 통신만 담당하며 OpenAI·Supabase에 직접 접속하지 않는다.

## 2. HTML 요소 계약
다음 ID를 사용한다. 이름을 바꾸려면 HTML과 JavaScript를 함께 수정하고 문서도 갱신한다.

| 요소 | ID | 역할 |
|---|---|---|
| 입력창 | `textInput` | 분석할 문장 |
| 글자 수 | `charCount` | 현재 글자 수 |
| 분석 버튼 | `analyzeButton` | 분석 요청 |
| 로딩 문구 | `loadingMessage` | 진행 상태 |
| 결과 영역 | `resultSection` | 성공 결과 컨테이너 |
| 감정 라벨 | `sentimentLabel` | 긍정/부정/중립 |
| 신뢰도 | `confidenceValue` | 정수 백분율 |
| 분석 이유 | `reasonText` | 한국어 설명 |
| 오류 영역 | `errorMessage` | 사용자 오류 |
| 다시 분석 | `resetButton` | 입력·결과 초기화 |

## 3. 입력 규칙
- 입력값 앞뒤 공백을 제거한 후 검증한다.
- 빈 문자열은 요청하지 않는다.
- 최대 길이는 2,000자다. HTML의 `maxlength`와 JavaScript 검증을 모두 적용한다.
- 글자 수는 사용자가 이해할 수 있도록 현재 글자 수와 최대 글자 수를 표시한다.
- Enter 키만으로 제출하지 않는다. 여러 줄 입력을 위해 버튼으로 제출한다.

## 4. API 통신 계약
- 메서드: `POST`
- 경로: `/api/analyze`
- 헤더: `Content-Type: application/json`
- 요청 본문:

```json
{
  "text": "오늘은 작은 일에도 감사한 마음이 들었다."
}
```

- 성공 응답:

```json
{
  "success": true,
  "data": {
    "id": "저장된 UUID",
    "sentiment": "positive",
    "confidence": 87,
    "reason": "감사와 만족을 나타내는 표현이 중심이어서 긍정으로 판단했습니다."
  }
}
```

- 실패 응답:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "분석할 문장을 입력해 주세요."
  }
}
```

## 5. 화면 동작
1. 제출 전 기존 오류 메시지를 지운다.
2. 요청 중 버튼을 비활성화하고 로딩 문구를 보인다.
3. `fetch()`로 API를 호출한다.
4. HTTP 상태 코드와 JSON의 `success`를 모두 확인한다.
5. 성공 시 이전 결과를 새 응답으로 교체한다.
6. 실패 시 이전 결과를 새 결과인 것처럼 남기지 않는다. 오류 영역에 메시지를 표시한다.
7. 요청이 끝나면 성공·실패와 관계없이 로딩을 종료하고 버튼을 복구한다.
8. 네트워크 오류도 사용자 메시지로 변환한다.

## 6. 결과 표시 규칙
- `positive` → “긍정”, `negative` → “부정”, `neutral` → “중립”.
- `confidence`는 `0%`~`100%`로 표시한다.
- 신뢰도 옆에 “AI가 추정한 참고 수치이며 정답 확률을 보장하지 않습니다.” 문구를 표시한다.
- `reason`은 `textContent`로 출력한다.
- 응답에 필수 값이 없거나 예상하지 못한 라벨이면 성공 화면을 만들지 않고 일반 오류를 표시한다.

## 7. 완료 기준
- 빈 값·공백만 있는 값은 요청하지 않는다.
- 2,000자까지 입력할 수 있고 초과 입력은 막는다.
- 로딩 중 연속 클릭으로 중복 요청이 발생하지 않는다.
- 성공 응답의 세 필드가 각각 올바른 위치에 나타난다.
- API 오류와 네트워크 오류가 화면에 표시된다.
- 사용자 입력이 HTML로 실행되지 않는다.
- 키보드와 모바일 터치로 조작할 수 있다.
