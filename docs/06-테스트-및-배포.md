# 06. 테스트, 검증 및 Vercel 배포

## 1. 테스트 환경
- Node.js LTS
- 로컬 Vercel 개발 서버
- 별도 개발용 OpenAI API 키
- 별도 개발용 Supabase 프로젝트
- 운영 DB와 테스트 DB를 분리한다. 테스트 데이터가 운영 데이터에 들어가지 않도록 한다.

## 2. 기능 테스트 케이스
| ID | 입력/상황 | 기대 결과 |
|---|---|---|

AI 결과는 문장마다 달라질 수 있으므로 테스트에서 특정 신뢰도 숫자를 고정하지 않는다. 세 라벨 분류는 대표 문장으로 확인하고, 결과 형식과 범위 검증은 별도 단위 테스트로 고정한다.

## 3. 자동 검증
- `npm run`으로 제공되는 스크립트를 확인한다.
- 입력 검증 함수와 AI 결과 스키마 검증은 단위 테스트를 작성한다.
- API 핸들러는 OpenAI·Supabase 호출을 대체할 수 있는 테스트 구조를 우선한다.
- HTML/CSS/JS 정적 파일 로딩과 브라우저 콘솔 오류를 확인한다.
- 테스트를 실행하지 못한 항목은 통과로 표시하지 않는다.

권장 검증 순서:
1. `npm install`
2. 프로젝트에서 정의한 테스트 명령 실행
3. `npm run dev`
4. 브라우저에서 기본 화면 확인
5. 대표 문장으로 성공 흐름 확인
6. 잘못된 입력과 API 오류 확인
7. 모바일 뷰포트와 키보드 접근성 확인

## 4. 로컬 실행
1. `.env.local` 파일을 만들고 `.env.example`의 변수를 채운다.
2. `npm install`을 실행한다.
3. `npx vercel dev` 또는 프로젝트에 정의한 `npm run dev`를 실행한다.
4. 터미널에 표시된 로컬 주소로 접속한다.
5. API 키가 없는 경우에도 정적 UI와 입력 검증은 확인할 수 있어야 한다.

## 5. Vercel 배포
1. 코드를 Git 저장소에 커밋한다. `.env.local`은 제외한다.
2. Vercel에서 저장소를 연결한다.
3. 프로젝트 설정에서 환경 변수를 등록한다: `OPENAI_API_KEY`, `OPENAI_MODEL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
4. Preview와 Production 환경을 구분해 키를 등록한다.
5. 배포를 실행한다.
6. 배포 URL에서 정상 분석, 잘못된 입력, 오류 메시지, DB 저장을 확인한다.
7. 로그에 입력 원문·API 키가 남지 않는지 확인한다.

## 6. 배포 완료 기준
- Vercel 빌드와 배포가 성공한다.
- 정적 페이지가 공개 URL에서 열린다.
- `/api/analyze`가 정상 요청에 응답한다.
- 분석 결과가 Supabase에 저장된다.
- API 키가 클라이언트 코드나 응답에 포함되지 않는다.
- 모바일 화면에서 기능을 사용할 수 있다.
- 배포 후 실제 환경 변수와 DB 권한을 확인했다.

## 7. 운영 전 확인할 항목
- 서비스 이용자에게 입력 텍스트 저장 사실을 고지했는가?
- 개인정보 처리방침과 보관·삭제 정책을 마련했는가?
- API 호출 제한과 비용 모니터링을 설정했는가?
- OpenAI 및 Supabase 사용량 한도를 확인했는가?
- 에러 로그에 민감한 입력이 포함되지 않는가?
